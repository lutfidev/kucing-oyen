# Kucing Oren

Game puzzle mobile (Flutter + Flame). Pemain menaruh benda (ikan, ember air, kardus) di papan 7x9, lalu Oyen si kucing oren bergerak sendiri mengikuti aturan tetap. Semua teks di dalam game memakai Bahasa Indonesia santai.

## Sumber kebenaran

- `docs/GDD.md`: dokumen desain game (aturan Oyen, elemen peta, alur level, bintang, 20 level).
- `docs/reference/oyen_simulator.py`: simulator + solver acuan. Logika simulasi Dart HARUS identik dengan file ini.
- `assets/levels/chapter1-2.json`: data 20 level (peta, baki, bintang 3, solusi, jumlah langkah solusi).
- `docs/design/`: ekspor desain UI dari Claude Design (warna, tipografi, layar). Baca `docs/design/source/` (hasil bongkar: 18 halaman, komponen `*.dc.html`, token warna di `13-design-token-komponen-ui.html`), bukan `Kucing Oren.html` yang berupa paket terkompresi 16 MB. Folder ini tidak ikut repo (`.gitignore`), hanya ada di komputer pemilik repo. Kalau tidak ada, beri tahu pemilik repo; jangan menebak isi desain.
- `docs/DESIGN_NOTES.md`: keputusan saat desain, GDD, dan data level tidak cocok (dibuat saat pertama dibutuhkan).

## Struktur

- `lib/game/sim/`: simulasi Dart murni. `simulate(board, placed)` → `SimResult` (`win`, `vaseBroken`, `steps`, `failReason`, `trace` berisi `SimStep` per langkah, `vaseBrokenAtStep`). `solve(board, inventory, {needSafe})` → `SolveResult` (`minItems`, `solutions`: semua susunan minimum tanpa duplikat) atau null. `Board.parse`, `Level`/`parseLevels`, `Cell`, `Direction` (`label` = arah layar: atas, kanan, bawah, kiri), `Item`/`Placement`, `Pos`. Impor lewat `sim/sim.dart`.
- `lib/game/model/level_session.dart`: `LevelSession(level)`, Dart murni. Fase `SessionPhase` (`arrange` → `running` → `result`). Aksi fase atur `place`/`move`/`remove` mengembalikan `false` kalau ditolak; `canPlaceAt(pos)` untuk petak menyala. `itemAt(pos)` hanya benda pemain (benda bawaan lewat `board.cellAt`), `placed`, `remaining` (sisa baki), `itemsUsed`. Pindah fase: `wake()` → `SimResult`, `finish()` ke layar hasil, `arrangeAgain()` (Atur Lagi/Coba Lagi, susunan tetap), `reset()` (Ulangi, papan kosong); pindah fase yang tidak sah melempar `StateError`. `stars` 0–3, null di fase atur.
- `lib/game/model/` fase jalan, Dart murni: `runFrames(board, result)` → `RunFrame` per langkah 0..`steps` (posisi, arah, `action`, `cleared` ikan dimakan/kardus penyok, `knocked`, `vaseBroken`, `atBowl`, `inBox`), dibangun ulang dari `trace` tanpa simulasi ulang (dipakai lagi untuk putar ulang). `RunClock(steps)`: langkah yang tampil (mulai 1), `tick(dt)`, `togglePause`, `toggleFast` (×2), `stepOnce`, `skipToEnd`, `done`, `RunClock.stepTime` 0,25 detik. `runCaption(board, frames, step)`: caption santai per `StepKind` dengan arah layar. Putar ulang (`replay.dart`): `replayTrail(frames)` → `TrailMark` per petak (`pos`, `steps`, `label` "2·3", "5–7", "12·24·…"), `replayCaptions(board, result, frames)` → caption rekap desain 09 untuk langkah 0..akhir (langkah terakhir yang gagal menyebut sebabnya).
- `lib/game/model/progress.dart` dan `chapter.dart`, Dart murni: `Progress` (bintang terbaik per level; `starsOf`, `isWon`, `isUnlocked` = level 1 atau level sebelumnya menang, `current(ids)` = level pertama yang belum menang, `record(id, stars)` hanya mencatat yang lebih baik, `totalStars`, `starsIn`, `toJson`/`fromJson` membuang entri rusak). `Chapter` (`number`, `name` dari `chapterNames`, `levels`, `title` "Babak 1 – Dapur", `boss` = level terakhir, `bossName` tanpa "BOS: ", `isUnlocked`, `isDone`, `stars`, `maxStars`), `chaptersOf(levels)`, `chapterToPlay` (babak yang dibuka "Main"), `chapterNumbered`, `chapterOfLevel`.
- `lib/game/model/hints.dart`, Dart murni: `coinsPerStar` (10), `coinsForStars(before, after)` (koin hanya untuk bintang baru), `maxHintTier` (3), `hintCost(tier)` (20/40/80), `hintMarks(level, tier)` → `Map<Pos, Item?>` (tingkat 1 petak `solution[0]` tanpa jenis, 2 dengan jenis, 3 seluruh solusi), `hintText(level, tier)`, `hintEffect(item)`, `noItemsHintText`.
- `lib/game/model/costumes.dart`, Dart murni: `Costume` (`id` = `OyenCostume`, `name`, `price`), `costumes` (urutan dan harga desain 12: Polos 0, Peci 60, Sarung 90, Topi Koki 150, Kacamata 45), `costumeOf(id)`, `Wardrobe` (`owned` selalu memuat Polos, `wearing` yang tidak dimiliki kembali ke Polos; `owns`, `canBuy(id, coins)`, `buy(id)` = dimiliki dan langsung dipakai, `wear(id)`, `actionFor(id, coins)` → `CostumeAction` wearing/wear/buy/notEnoughCoins, `Wardrobe.initial`).
- `lib/game/model/rewards.dart`, Dart murni: `dailyBonusCoins` (20), `adRewardCoins` (20), `maxAdsPerDay` (5), `dayNumber(DateTime)` (nomor hari kalender lokal), `DailyRewards` (`bonusDay`, `adDay`, `adsWatched`; `canClaimBonus(today)`, `adsLeft(today)`, `claimBonus`, `watchedAd`; jam mundur menahan bonus dan iklan; `toJson`/`fromJson` membuang field rusak).
- `lib/game/model/rules.dart`, Dart murni: `OyenRule` (`knock`, `fish`, `water`, `wall`, `box`, urut kartu desain 05; `level` = level pengenalan, `number` 1–5, `isLearned(progress, levelId)` = level itu sudah terbuka atau sedang dimainkan level itu/sesudahnya), `learnedRules(progress, levelId)`.
- `lib/game/level_loader.dart`: `loadLevels()` membaca aset level lewat `rootBundle` tanpa cache (lihat catatan test di bawah); dipanggil sekali di `main`.
- `lib/game/kucing_game.dart`: `KucingGame` (`FlameGame`, kamera resolusi tetap 350×450 = koordinat papan desain). Layar mengisi `scene` (`BoardScene`); `tileAtPoint`/`tileAtGlobal` menerjemahkan titik ke `Pos`; seretan di papan diteruskan ke `BoardInput.pickUp(tile, global)` yang mengembalikan `Drag` (atau null). Mesin hanya jalan selama ada petak menyala yang berkedip atau Oyen digeser (`animate`), selain itu berhenti sendiri supaya `pumpAndSettle` selesai. `moveTime` (detik, 0 = langsung pindah): saat petak Oyen di `scene` berganti, `CatComponent` menggesernya dengan kurva `ease`; `oyenShown` = posisi yang sedang tampil. `lib/game/components/`: `BoardComponent` (petak, jalur, seret) dan `CatComponent` (Oyen), keduanya menggambar lewat `lib/game/render/`. Tidak ada aturan main di sini; semuanya di `LevelSession`.
- `lib/game/render/`: gambar petak, Oyen, dan papan sebagai fungsi `Canvas` (untuk `CustomPainter` maupun Flame), impor lewat `render/render.dart`. Data Dart murni: `Tile` (`TileKind`, `TileItem`, `alt`, `glow`, `ghost` = benda petunjuk samar di atas kotak menyala, opasitas `ItemArt.hintOpacity` 0,7; `Tile.size` 50), `OyenLook` (`OyenPose`, `Direction`, `OyenCostume`, `OyenBubble` termasuk `ikan` gelembung pikiran, `mirror`, `label`), `BoardScene.fromMap(map, items, glow, ghosts, broken, knocked, oyen, showOyen, facing, path, trail)` (port `Board.dc.html`, 63 petak + `BoardOyen` berkolom/baris pecahan + jalur putus-putus + nomor jejak `BoardMark`; `items` berisi `TileItem.none` menghapus benda bawaan; `designMap`; `dressed(costume)` = papan yang sama dengan Oyen berkostum). Fase jalan: `runLook(frame)` (pose per `StepKind`), `runScene(map, placed, frames, step)`; layar gagal: `restScene(map, placed, frames)` (papan terakhir, Oyen tidur lagi); putar ulang: `replayScene(map, placed, frames, trail, step)` (seluruh jalur, nomor jejak langkah ini menyala, langkah 0 Oyen tidur tanpa Zzz). Penggambar: `paintTile(canvas, tile, glowOpacity)`, `paintOyen(canvas, look, size)`, `paintBoardFrame`, `paintBoard(canvas, scene, glowOpacity, oyenAt)` (= `paintBoardTiles` + `paintBoardPath` + `paintBoardTrail` + `paintBoardOyen(at:)`, untuk dua komponen Flame), `tileGlowOpacity(detik)`, `BoardArt` (ukuran Oyen 62, geser (-6, -12)). Benda pemain di baki dan di tangan (desain 03): `paintItemArt(canvas, item, ghost)`, `paintLiftedItem(canvas, item, shadow)`, `ItemArt` (ukuran dan posisi benda diseret, `ItemArt.tileItem(item)` → `fishP`/`bucketP`/`boxP`). Layar hasil (desain 06, 07): `ResultArt` (ukuran, letak, dan gerak ilustrasi), `paintRays`, `paintSuccessBowl`, `paintVaseBowl`, Lemari Kostum (desain 12) `paintCloset`/`ClosetArt.viewBox`, `paintVaseScene(momShift:, prangAngle:)`. Beranda dan peta babak (desain 01, 02): `MapArt` (titik node `points`, jejak kaki `pawsBetween`/`pawAngle`, `mapTop`/`headerFade`, denyut, ukuran kotak bos), `paintHomePaws(canvas, size)`, `paintChapterIcon(canvas, chapter)`, `paintBossArt(canvas, chapter)`, `paintBossArea`. Kartu aturan dan tutorial (desain 05, 11): `RuleArt` (kartu 76, `quarterAngle` kucing kartu 4, tangan `hand`/`handTip`/`handOffset`, cincin `ringSpread`/`ringTime`), `paintRuleArt(canvas, rule, learned:, catAngle:)`, `paintTutorialHand`. Koin (desain 01, 10): `paintCoin(canvas, plain:)`, `CoinArt.viewBox` 28. Isi `<svg>` desain disalin utuh di `design_svg.dart` dan diurai `SvgTemplate` (`SvgDrawing.bounds` = kotak `fill-box`, `opacity` juga di `<g>`); jangan diketik ulang.
- `lib/theme/`: token desain sebagai `ThemeExtension` per grup: `KoColors`, `KoType` (display, title, heading, number, body, label, overline, plus gaya tombol/chip/badge, teks kecil `chipLabel`, `bodySmall`, `caption`, fase jalan `numberMedium`, `numberBadge`, `paragraph`, `controlLabel`, layar hasil `overlineLarge`, `headline`, `headlineSmall`, `numberCompact`, dan Beranda/peta `logo`, `logoSmall`, `bodyLarge`, `numberChip`, `numberChipSmall`, `tag`, `tagSmall`, putar ulang `headingLarge`, `paragraphSmall`, `numberTick`, kartu aturan `cardTitle`, `cardBody`, `cardBodyStrong`, `numberRule`, tutorial `dialogTitle`), `KoSpace`, `KoRadius`, `KoShadow`, `KoSize`. `KoTheme.light()` memasang semuanya; widget membaca lewat `context.koColors`, `context.koType`, `context.koSpace`, `context.koRadius`, `context.koShadow`, `context.koSize`. ## Aturan penting

- Logika simulasi ditulis sebagai Dart murni di `lib/game/sim/`, tanpa import Flame atau Flutter, supaya bisa diuji dengan unit test.
- Urutan aturan per langkah: sampai mangkuk → duduk di kardus → jatuhkan barang di meja sebelah → kejar ikan terdekat yang terlihat → cek petak depan (air: putar balik, tembok/meja: berputar searah jarum jam, kardus: masuk duduk 2 langkah, ikan: makan, lantai/mangkuk: maju).
- Seri jarak ikan: depan → searah jarum jam → berlawanan jarum jam → belakang.
- Gagal: keadaan berulang (mondar-mandir) atau lewat 80 langkah. Vas pecah tidak menggagalkan level, hanya menghapus bintang 2 dan 3.
- Huruf peta: `#` tembok, `.` lantai, `T` mangkuk, `M` meja, `G` meja+gelas, `V` meja+vas, `F` ikan bawaan, `A` genangan air, `K` kardus bawaan, `^ > v <` Oyen (huruf kecil `v` = menghadap bawah).
- Teks aturan memakai "berputar searah jarum jam", bukan "belok kanan". Teks cerita/caption memakai arah layar (atas, bawah, kiri, kanan).

## Alur git per langkah roadmap

Pemilik repo biasanya `/clear` setelah tiap sesi, jadi aturan ini yang berlaku, bukan ingatan percakapan. Kerjakan sendiri tanpa bertanya dan tanpa menyuruh pemilik repo menjalankan perintah:

- **Awal langkah:** `git fetch`, pastikan tidak ada PR terbuka (`gh pr list --state open` kosong) dan PR langkah sebelumnya sudah di-merge ke `origin/main`, lalu `git checkout main && git pull --ff-only`, buat `feat/<nama-langkah>`, hapus branch lokal yang sudah di-merge, `flutter pub get && flutter analyze && flutter test`. Kalau masih ada PR yang belum di-merge, jangan bercabang dari `main` lama; beri tahu pemilik repo. (Langkah 1 masuk langsung ke `main` tanpa PR.)
- **Selama langkah:** commit kecil, pesan bahasa Inggris singkat (`feat(sim): ...`, `fix: ...`, `test: ...`, `docs: ...`).
- **Akhir langkah** (analyze bersih, test hijau, temuan review sudah diperbaiki, langkah sudah dicentang di `docs/ROADMAP.md`): `git push -u origin <branch>` lalu `gh pr create --base main` langsung, tanpa menu pilihan. Kirim link PR-nya. Judul PR `feat: <nama langkah>`. Badan PR berbahasa Indonesia: kalimat pembuka "Langkah N roadmap: ...", daftar perubahan, asumsi baru (kalau ada, juga dicatat di `docs/DESIGN_NOTES.md`), lalu baris "Verifikasi:" berisi hasil `flutter analyze`, jumlah test `flutter test` yang lulus, dan cek lain yang dijalankan.
- **Merge PR** dilakukan pemilik repo di GitHub; jangan merge sendiri kecuali diminta.
- **Atribusi:** commit dan PR atas nama akun git pemilik repo. Jangan tambahkan `Co-Authored-By: Claude`, "Generated with Claude Code", atau atribusi Claude lain di pesan commit maupun badan PR.
- Kesepakatan baru soal alur kerja langsung dicatat di file ini, jangan hanya diucapkan di chat.

## Skill dan effort

Pemilik repo nyaman dengan skill superpowers: selalu pakai skill yang cocok. Effort sesi utama diatur pemilik repo lewat `/effort`; effort subagent ditulis di sini dan berlaku sebagai permintaan pemilik repo.

- **Planning:** `superpowers:brainstorming` lalu `superpowers:writing-plans` di sesi utama (high; xhigh untuk langkah dengan banyak keputusan seperti 12, 14, dan 15). Brainstorming hanya untuk hal yang belum diputuskan prompt roadmap, GDD, atau desain, dan pertanyaan yang diminta prompt roadmap (mis. sumber koin di langkah 12) diajukan di sini. Jalankan rencana dengan `superpowers:executing-plans` di sesi utama, bukan `subagent-driven-development`.
- **Cari bug:** `superpowers:systematic-debugging` di sesi utama (high). Kalau penyebabnya bisa di banyak tempat, sebar pencarian ke subagent `Explore` effort low; analisis akar masalah tetap di sesi utama.
- **Cari kode yang lebar:** subagent `Explore` effort low, hanya kalau bagian "Struktur" di atas dan `grep` langsung tidak cukup.
- **Review sebelum PR:** `superpowers:requesting-code-review` dengan satu subagent effort high, lalu `superpowers:receiving-code-review` untuk menimbang temuannya sebelum diperbaiki. Sesudah itu `superpowers:verification-before-completion` sebelum push.
- **Desain, logo, ikon, dan gambar lain:** di sesi utama (high), bukan subagent, karena butuh konteks desain lengkap. Yang ada di `docs/design/source/` disalin persis; yang belum ada desainnya (mis. ikon launcher dan splash di langkah 15) mulai dengan `superpowers:brainstorming`, pakai palet dan gaya desain, cek hasilnya lewat potret layar `test/screenshots/`, lalu catat di `docs/DESIGN_NOTES.md`.
