# Kucing Oren

Game puzzle mobile (Flutter + Flame). Pemain menaruh benda (ikan, ember air, kardus) di papan 7x9, lalu Oyen si kucing oren bergerak sendiri mengikuti aturan tetap. Semua teks di dalam game memakai Bahasa Indonesia santai.

## Sumber kebenaran

- `docs/GDD.md`: dokumen desain game (aturan Oyen, elemen peta, alur level, bintang, 20 level).
- `docs/reference/oyen_simulator.py`: simulator + solver acuan. Logika simulasi Dart HARUS identik dengan file ini.
- `assets/levels/chapter1-2.json`: data 20 level (peta, baki, bintang 3, solusi, jumlah langkah solusi).
- `docs/design/`: ekspor desain UI dari Claude Design (warna, tipografi, layar). Baca `docs/design/source/` (hasil bongkar: 18 halaman, komponen `*.dc.html`, token warna di `13-design-token-komponen-ui.html`), bukan `Kucing Oren.html` yang berupa paket terkompresi 16 MB. Folder ini tidak ikut repo (`.gitignore`), hanya ada di komputer pemilik repo. Kalau tidak ada, beri tahu pemilik repo; jangan menebak isi desain.
- `docs/DESIGN_NOTES.md`: keputusan saat desain, GDD, dan data level tidak cocok (dibuat saat pertama dibutuhkan).

## Struktur

- `lib/game/sim/`: simulasi Dart murni. `simulate(board, placed)` → `SimResult` (`win`, `vaseBroken`, `steps`, `failReason`, `trace` berisi `SimStep` per langkah, `vaseBrokenAtStep`). `solve(board, inventory, {needSafe})` → `SolveResult` (`minItems`, `solutions`: semua susunan minimum tanpa duplikat) atau null. `Board.parse`, `Level`/`parseLevels`, `Cell`, `Direction` (`label` = arah layar: atas, kanan, bawah, kiri), `Item`/`Placement`, `Pos`. Impor lewat `sim/sim.dart`.
- `lib/game/model/level_session.dart`: `LevelSession(level)`, Dart murni. Fase `SessionPhase` (`arrange` → `running` → `result`). Aksi fase atur `place`/`move`/`remove` mengembalikan `false` kalau ditolak; `canPlaceAt(pos)` untuk petak menyala. `itemAt(pos)` hanya benda pemain (benda bawaan lewat `board.cellAt`), `placed`, `remaining` (sisa baki), `itemsUsed`. Pindah fase: `wake()` → `SimResult`, `finish()` ke layar hasil, `arrangeAgain()` (Atur Lagi/Coba Lagi, susunan tetap), `reset()` (Ulangi, papan kosong); pindah fase yang tidak sah melempar `StateError`. `stars` 0–3, null di fase atur.
- `lib/game/model/` fase jalan, Dart murni: `runFrames(board, result)` → `RunFrame` per langkah 0..`steps` (posisi, arah, `action`, `cleared` ikan dimakan/kardus penyok, `knocked`, `vaseBroken`, `atBowl`, `inBox`), dibangun ulang dari `trace` tanpa simulasi ulang (dipakai lagi untuk putar ulang). `RunClock(steps)`: langkah yang tampil (mulai 1), `tick(dt)`, `togglePause`, `toggleFast` (×2), `stepOnce`, `skipToEnd`, `done`, `RunClock.stepTime` 0,25 detik. `runCaption(board, frames, step)`: caption santai per `StepKind` dengan arah layar.
- `lib/game/level_loader.dart`: `loadLevels()` membaca aset level lewat `rootBundle` tanpa cache (lihat catatan test di bawah).
- `lib/game/kucing_game.dart`: `KucingGame` (`FlameGame`, kamera resolusi tetap 350×450 = koordinat papan desain). Layar mengisi `scene` (`BoardScene`); `tileAtPoint`/`tileAtGlobal` menerjemahkan titik ke `Pos`; seretan di papan diteruskan ke `BoardInput.pickUp(tile, global)` yang mengembalikan `Drag` (atau null). Mesin hanya jalan selama ada petak menyala yang berkedip atau Oyen digeser (`animate`), selain itu berhenti sendiri supaya `pumpAndSettle` selesai. `moveTime` (detik, 0 = langsung pindah): saat petak Oyen di `scene` berganti, `CatComponent` menggesernya dengan kurva `ease`; `oyenShown` = posisi yang sedang tampil. `lib/game/components/`: `BoardComponent` (petak, jalur, seret) dan `CatComponent` (Oyen), keduanya menggambar lewat `lib/game/render/`. Tidak ada aturan main di sini; semuanya di `LevelSession`.
- `lib/game/render/`: gambar petak, Oyen, dan papan sebagai fungsi `Canvas` (untuk `CustomPainter` maupun Flame), impor lewat `render/render.dart`. Data Dart murni: `Tile` (`TileKind`, `TileItem`, `alt`, `glow`; `Tile.size` 50), `OyenLook` (`OyenPose`, `Direction`, `OyenCostume`, `OyenBubble` termasuk `ikan` gelembung pikiran, `mirror`, `label`), `BoardScene.fromMap(map, items, glow, broken, knocked, oyen, showOyen, facing, path)` (port `Board.dc.html`, 63 petak + `BoardOyen` berkolom/baris pecahan + jalur putus-putus; `items` berisi `TileItem.none` menghapus benda bawaan; `designMap`). Fase jalan: `runLook(frame)` (pose per `StepKind`), `runScene(map, placed, frames, step)`; layar gagal: `restScene(map, placed, frames)` (papan terakhir, Oyen tidur lagi). Penggambar: `paintTile(canvas, tile, glowOpacity)`, `paintOyen(canvas, look, size)`, `paintBoardFrame`, `paintBoard(canvas, scene, glowOpacity)` (= `paintBoardTiles` + `paintBoardPath` + `paintBoardOyen(at:)`, untuk dua komponen Flame), `tileGlowOpacity(detik)`, `BoardArt` (ukuran Oyen 62, geser (-6, -12)). Benda pemain di baki dan di tangan (desain 03): `paintItemArt(canvas, item, ghost)`, `paintLiftedItem(canvas, item, shadow)`, `ItemArt` (ukuran dan posisi benda diseret, `ItemArt.tileItem(item)` → `fishP`/`bucketP`/`boxP`). Layar hasil (desain 06, 07): `ResultArt` (ukuran, letak, dan gerak ilustrasi), `paintRays(turns:)`, `paintSuccessBowl`, `paintVaseBowl`, `paintVaseScene(momShift:, prangAngle:)`. Isi `<svg>` desain disalin utuh di `design_svg.dart` dan diurai `SvgTemplate` (`SvgDrawing.bounds` = kotak `fill-box`); jangan diketik ulang.
- `lib/theme/`: token desain sebagai `ThemeExtension` per grup: `KoColors`, `KoType` (display, title, heading, number, body, label, overline, plus gaya tombol/chip/badge, teks kecil `chipLabel`, `bodySmall`, `caption`, fase jalan `numberMedium`, `numberBadge`, `paragraph`, `controlLabel`, dan layar hasil `overlineLarge`, `headline`, `headlineSmall`, `numberCompact`), `KoSpace`, `KoRadius`, `KoShadow`, `KoSize`. `KoTheme.light()` memasang semuanya; widget membaca lewat `context.koColors`, `context.koType`, `context.koSpace`, `context.koRadius`, `context.koShadow`, `context.koSize`. Tidak ada warna atau ukuran hardcode di widget; tambah token kalau butuh nilai baru. Font Fredoka/Nunito dibundel di `assets/fonts/` (`KoFonts`).
- `lib/widgets/`: komponen dasar, impor lewat `widgets/widgets.dart`. `TileView`, `OyenView`, `BoardView`, `ItemArtView`, `LiftedItemView` (`game_art.dart`, membungkus `lib/game/render/`), `KoButton` (`KoButtonKind` primary/success/secondary, `KoButtonSize` hero/large/medium, `icon` di kiri dan `trailingIcon` di kanan label), `KoIconButton` (`KoIconButtonTone`, opsional `label`), `KoPressable` (bayangan padat yang hilang saat ditekan, opsional `toggled`), `KoChip` / `KoChip.dark` (`large` 44 px untuk penghitung langkah), `TraySlot` (slot baki + badge sisa), `KoCard` (`locked`, `elevated`), `KoStar` (`strokeWidth`, `shine`)/`KoStars`, `KoIcon` + `KoIcons` (path SVG dari desain; `KoIconData.viewBox` untuk viewBox selain 0 0 24 24), `KoDashedBorder`.
- `lib/app/`: `KucingOrenApp` (`MaterialApp.router`), `createRouter()`, `AppRoutes` (`/` Beranda sementara dengan tombol ke level 1–20, `/galeri`, `/galeri/papan`, `/galeri/oyen`, `AppRoutes.level(id)` = `/level/:id`). `lib/screens/<layar>/` untuk layar, `lib/gallery/` untuk galeri: token dan komponen (`gallery_screen.dart`), petak dan papan, sprite Oyen; kerangka bersama `GalleryPage`, `GallerySection`, `GalleryGrid`.
- `lib/screens/level/`: `LevelScreen` (rute, memuat level lalu `LevelView`), `LevelView` (pegang `LevelSession` dan `KucingGame`, menerjemahkan seretan dari baki dan papan: lepas di petak menyala = `place`/`move`, benda papan dilepas di luar papan = `remove`; setelah `wake()` memutar langkah lewat `Ticker` + `RunClock`, lalu "Lihat hasil" = `finish()` dan `ResultView` menutupi layar level yang tetap terpasang (`Offstage`); `onNext` = Lanjut; bagian bawah setinggi sama di fase atur dan fase jalan supaya papan tidak berubah ukuran). `LevelScreen` mengisi `onNext` dengan level berikutnya (sesudah level terakhir: Beranda), `LevelBoard` (`GameWidget` + bingkai, skala menyesuaikan tempat), `LevelTopBar` (`trailing`: `RulesButton` atau `StepCounter`), `TargetChip`, `run_panel.dart` (fase jalan desain 04: `StepCounter`, `RunStatus`, `RunCaption`, `RunControls`, `RunDoneButton`), `TrayPanel` (slot yang bisa diseret, `TrayDragStart`), `TrayMessage`, `TrayBox`, `itemName(item)`.
- `lib/screens/result/`: layar hasil di dalam rute level (tanpa rute sendiri). `ResultView(session, onArrange, onRestart, onNext, onReplay)` memilih `SuccessResult` (desain 06, 2–3 bintang), `VaseResult` (07), atau `BoredResult` (08, mondar-mandir dan kelamaan). `result_parts.dart`: `ResultPage`, `ResultHeader`, `ResultStars` (animasi `koStar`), `ResultStat`/`ResultStats`, `ResultRule`/`ResultRules`, `ResultButtons`, `ResultArtSlot` (kartu ilustrasi mengecil, hilang di bawah `KoSize.artMinScale`). `result_art.dart`: `ResultRays`, `ResultArtCard`, `SuccessArt`, `VaseArt`, `RestBoard` (papan pudar + chip), `RestBadge`. Putar ulang (`onReplay`) masih null sampai langkah 10.
- `test/game/`: test simulasi, solver, loader, sesi level, fase jalan (`model/run_*_test.dart`, `render/run_scene_test.dart`: pose dan posisi level 13 dan 15), `KucingGame`, dan gambar (`render/`: pemetaan peta, `SvgTemplate`, warna piksel di koordinat desain, dan `design_sync_test.dart` yang hanya jalan kalau `docs/design/` ada). `test/widgets/`, `test/theme/`: test komponen dan token. `test/screens/level_view_test.dart`: seret dari baki dan di papan lewat helper `_dragToTile`/`_dragTile` (posisi petak dihitung dari kotak `GameWidget`), level dibaca langsung dari berkas JSON; grup `fase jalan` memajukan waktu dengan `tester.pump(RunClock.stepTime)` (satu tick tidak memajukan lebih dari satu langkah, jadi waktu panjang dipompa per bingkai).
- `test/screens/result_view_test.dart`: layar hasil dari `LevelSession` langsung; contoh hasil bersama (`levels`, `resultOf`, `fishOnly`, `twoStars`, `longWalk` = peta 7×9 yang kelamaan, `pumpFor`) di `test/screens/result_fixtures.dart`. Sinar layar Berhasil dan "PRANG!" layar vas pecah bergerak terus: di kedua layar itu jangan `pumpAndSettle`, majukan waktu per bingkai (`pumpFor`) atau pakai `disableAnimations`.
- `test/screens/overflow_test.dart`: semua rute di 360×640 sampai 412×915, teks 100% dan 130%. Rute baru wajib ditambahkan ke daftar `routes`. Fase jalan level 1, 12, 13 juga diputar sampai layar hasil, dan kelima jenis layar hasil dipompa langsung dari sesi.
- `test/screenshots/`: potret layar, `flutter test test/screenshots --dart-define=SCREENSHOTS=true` → `build/screenshots/390x844/*.png` (dilewati di test biasa). `test/flutter_test_config.dart` memuat font asli untuk semua test. Helper test di `test/test_helpers.dart` (`pumpApp`, `pumpThemed`, `setScreenSize`, `setTextScale`). `rootBundle.loadString` menyimpan Future-nya di cache, dan Future itu terikat zona test yang pertama membuatnya: test berikutnya di file yang sama menunggu selamanya, bahkan dengan `runAsync`. Karena itu `loadLevels()` memakai `cache: false`; aset lain yang dimuat di widget test juga harus begitu, atau datanya diberikan langsung ke widget.

Setiap langkah roadmap memperbarui bagian ini kalau menambah folder atau API penting.

## Aturan penting

- Logika simulasi ditulis sebagai Dart murni di `lib/game/sim/`, tanpa import Flame atau Flutter, supaya bisa diuji dengan unit test.
- Urutan aturan per langkah: sampai mangkuk → duduk di kardus → jatuhkan barang di meja sebelah → kejar ikan terdekat yang terlihat → cek petak depan (air: putar balik, tembok/meja: berputar searah jarum jam, kardus: masuk duduk 2 langkah, ikan: makan, lantai/mangkuk: maju).
- Seri jarak ikan: depan → searah jarum jam → berlawanan jarum jam → belakang.
- Gagal: keadaan berulang (mondar-mandir) atau lewat 80 langkah. Vas pecah tidak menggagalkan level, hanya menghapus bintang 2 dan 3.
- Huruf peta: `#` tembok, `.` lantai, `T` mangkuk, `M` meja, `G` meja+gelas, `V` meja+vas, `F` ikan bawaan, `A` genangan air, `K` kardus bawaan, `^ > v <` Oyen (huruf kecil `v` = menghadap bawah).
- Teks aturan memakai "berputar searah jarum jam", bukan "belok kanan". Teks cerita/caption memakai arah layar (atas, bawah, kiri, kanan).

## Wajib sebelum selesai

- `flutter analyze` bersih (`No issues found!`).
- `flutter test` lulus, termasuk test yang menjalankan solusi ke-20 level dari `chapter1-2.json`: setiap solusi harus menang, vas tidak pecah, dan jumlah langkahnya sama dengan `solutionSteps`.
- Perintah `/check` (`.claude/commands/check.md`) menjalankan format, analyze, dan test sekaligus.

## Alur git per langkah roadmap

Pemilik repo biasanya `/clear` setelah tiap sesi, jadi aturan ini yang berlaku, bukan ingatan percakapan. Kerjakan sendiri tanpa bertanya dan tanpa menyuruh pemilik repo menjalankan perintah:

- **Awal langkah:** `git fetch`, pastikan tidak ada PR terbuka (`gh pr list --state open` kosong) dan PR langkah sebelumnya sudah di-merge ke `origin/main`, lalu `git checkout main && git pull --ff-only`, buat `feat/<nama-langkah>`, hapus branch lokal yang sudah di-merge, `flutter pub get && flutter analyze && flutter test`. Kalau masih ada PR yang belum di-merge, jangan bercabang dari `main` lama; beri tahu pemilik repo. (Langkah 1 masuk langsung ke `main` tanpa PR.)
- **Selama langkah:** commit kecil, pesan bahasa Inggris singkat (`feat(sim): ...`, `fix: ...`, `test: ...`, `docs: ...`).
- **Akhir langkah** (analyze bersih, test hijau, temuan review sudah diperbaiki, langkah sudah dicentang di `docs/ROADMAP.md`): `git push -u origin <branch>` lalu `gh pr create --base main` langsung, tanpa menu pilihan. Kirim link PR-nya. Judul PR `feat: <nama langkah>`. Badan PR berbahasa Indonesia: kalimat pembuka "Langkah N roadmap: ...", daftar perubahan, asumsi baru (kalau ada, juga dicatat di `docs/DESIGN_NOTES.md`), lalu baris "Verifikasi:" berisi hasil `flutter analyze`, jumlah test `flutter test` yang lulus, dan cek lain yang dijalankan.
- **Merge PR** dilakukan pemilik repo di GitHub; jangan merge sendiri kecuali diminta.
- **Atribusi:** commit dan PR atas nama akun git pemilik repo. Jangan tambahkan `Co-Authored-By: Claude`, "Generated with Claude Code", atau atribusi Claude lain di pesan commit maupun badan PR.
- Kesepakatan baru soal alur kerja langsung dicatat di file ini, jangan hanya diucapkan di chat.
